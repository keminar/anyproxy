# 缓存机制

anyproxy 有几个**进程内内存缓存**（[utils/cache/cache.go](../utils/cache/cache.go)），无需配置、随进程退出丢失、TTL 都很短，配置热重载不会主动清空（很快自然过期）。它们影响可观察行为，排查时值得了解。

> 全部是**进程私有内存态，不落盘、不跨进程**。anyproxy 一重启，所有缓存归零——所以「陈旧缓存」只可能发生在 anyproxy **不重启**、而外部（上级代理 / 上游 DNS）发生变化的这段窗口里。

## 1. DNS 解析缓存（ResolveLookup）

- **内容**：域名 → IPv4，以及一个 dial 状态（正常 / 失败）。
- **TTL**：解析成功缓存 **10 分钟**；`auto` 模式下本地 dial 失败的记录缓存 **20 秒**（`autoDirectFailTTL`）。
- **作用**：
  - 减少对同一域名的重复 DNS 解析；
  - 加速 `auto` 决策——某域名本地拨不通时，20 秒内直接按「失败」走远程，不再每次都本地重试、白等（见 [proxy-decision.md](proxy-decision.md)）。
- 容量上限约 65536 条，满了按环形覆盖最旧的。

> **配了 `hosts[].ip` 的域名不吃这个缓存**：这类域名直接读配置里的固定 IP（[proto/tunnel.go](../proto/tunnel.go) `if host.IP != "" { dstIP = host.IP }`），既不查也不写解析缓存。所以**改配置文件里的 `ip` 会随热重载立即生效，不用等 10 分钟**。真正吃这个 10 分钟缓存的，只有那些靠真实 DNS 解析、没配 `ip` 的域名。

## 2. auto 直连失败缓存（复用 ResolveLookup 的 StateFail）

- **内容**：`auto` 模式下本地直连失败的「域名 → StateFail」标记。
- **TTL**：**20 秒**（`autoDirectFailTTL`）。
- **机制**：`target=auto` 会先真直连；直连失败就记这个短标记，有效期内后续请求**跳过直连、直接走代理**，不再让一个页面并发的每条请求都去重试那个刚拨不通的直连、各白等一次超时。过期后重新尝试直连，以便及时发现直连恢复。
- **性质**：只影响**选路**（直连↔代理），不是「服务不可用」判定；两条路通常都通，最坏是 20 秒内多走代理。

## 3. 嗅探域名缓存（SniffName）

- **内容**：`hosts` 里配了 `ip` 的域名，其 `ip → 域名` 映射（DNS 劫持时记录）。
- **TTL**：**10 分钟**。
- **作用**：TUN/WinDivert 下，浏览器**预连接(preconnect)**会先建 TCP 但不发数据，导致 TCP 首包嗅探不到 SNI/Host。此时按目标 IP 反查这张表还原出客户端刚解析过的真实域名，让**按域名的规则仍然生效**（否则只能退化成按 IP 匹配）。
- key 恒为配置里的固定 `hosts.ip`，条目数受配置规模约束（通常几十条），惰性删除过期项。即便 10 分钟内陈旧也无害——key 是你写死的配置 IP，且每次 DNS 劫持都会覆盖写入。

## 4. 上级代理连通性：不再缓存（已移除）

早期版本对上级代理做过「不可用缓存」（`ProxyDial`，失败后 20 秒内跳过探测，日志 `proxy ... unavailable (cached)`）。**该缓存已移除**：它会导致「**上级代理重启恢复后、anyproxy 仍在旧失败缓存有效期内把它判死**」，请求无响应。

现在的行为（[proto/tunnel.go](../proto/tunnel.go) `getProxyServer`）：

- **每次用上级代理前都实拨探测**（`200ms` 建连即返回），不再有失败缓存；
- 代理挂了当次直接失败/回退，代理一恢复**下一个请求立刻可用**，无需等任何 TTL。

> 权衡：去掉缓存后，上级代理若长时间挂着，期间每条走代理的请求都会各花最多 200ms 探测。换来的是「重启即恢复、不再被缓存挡住」，对本项目是更优的取舍。

## 说明

- 以上缓存都是内存态、进程私有，不落盘、不跨进程；平滑重启的新进程从空缓存开始。
- 想立即看到配置/网络变化的效果，可重启进程；否则等 TTL（10 分钟 / 20 秒）自然过期。**注意**：配了 `ip` 的域名和上级代理均**不受缓存影响**（前者热重载即生效，后者每次实拨）。
- 调试级别 `-debug 3` 会打印 DNS 解析缓存的 HIT/MISS/EXPIRED，便于排查「为什么还走旧 IP / 旧决策」。

> 另有几个**平台专属**的短寿命运行态映射（非通用缓存）：Windows WinDivert 的 pid→exe 名（30s，防 PID 复用误判）、端口→pid（25ms）、NAT 连接表（按 idle/close 回收）；TUN 的 UDP 负缓存（2s）、在途 DNS（5s）。它们服务于各自子系统，见 [windows-windivert-redirect.md](windows-windivert-redirect.md) 等对应文档。
