# 缓存机制

anyproxy 有三个**进程内内存缓存**（[utils/cache/cache.go](../utils/cache/cache.go)），无需配置、随进程退出丢失、TTL 都很短，配置热重载不会主动清空（很快自然过期）。它们影响可观察行为，排查时值得了解。

## 1. DNS 解析缓存（ResolveLookup）

- **内容**：域名 → IPv4，以及一个 dial 状态（正常 / 失败）。
- **TTL**：解析成功缓存 **10 分钟**；`auto` 模式下本地 dial 失败的记录缓存 **20 秒**（`autoDirectFailTTL`）。
- **作用**：
  - 减少对同一域名的重复 DNS 解析；
  - 加速 `auto` 决策——某域名本地拨不通时，20 秒内直接按「失败」走远程，不再每次都本地重试、白等（见 [proxy-decision.md](proxy-decision.md)）。
- 容量上限约 65536 条，满了按环形覆盖最旧的。

## 2. 上游代理连通性缓存（ProxyDial）

- **内容**：最近探测「不可用」的上游代理地址（`host:port`）及其过期时间。
- **机制**：连上游代理前先用 **300ms** 拨号探测连通性；
  - 探测失败 → 标记该代理 **20 秒**（`proxyFailTTL`）内不可用，期间**直接跳过探测**，不再每个请求都白等 300ms；
  - 探测成功 → **立即清除**标记，恢复的代理马上可用。
- **作用**：`proxy: a, b, c` 多代理按序选可用的时，挂掉的代理能被快速跳过，不拖慢每个请求。

## 3. 嗅探域名缓存（SniffName）

- **内容**：`hosts` 里配了 `ip` 的域名，其 `ip → 域名` 映射（DNS 劫持时记录）。
- **TTL**：**10 分钟**。
- **作用**：TUN/WinDivert 下，浏览器**预连接(preconnect)**会先建 TCP 但不发数据，导致 TCP 首包嗅探不到 SNI/Host。此时按目标 IP 反查这张表还原出客户端刚解析过的真实域名，让**按域名的规则仍然生效**（否则只能退化成按 IP 匹配）。
- key 恒为配置里的固定 `hosts.ip`，条目数受配置规模约束（通常几十条），惰性删除过期项。

## 说明

- 三个缓存都是内存态、进程私有，不落盘、不跨进程；平滑重启的新进程从空缓存开始。
- 想立即看到配置/网络变化的效果，可重启进程；否则等 TTL（10 分钟 / 20 秒）自然过期。
- 调试级别 `-debug 3` 会打印 DNS 解析缓存的 HIT/MISS/EXPIRED，便于排查「为什么还走旧 IP / 旧决策」。
